# Развёртывание на GitHub

Всё крутится на GitHub Actions: по расписанию поднимается виртуалка Ubuntu, рендерит ролик,
выкладывает на YouTube и гасится. Свой компьютер держать включённым не нужно.

---

## Шаг 1. Репозиторий

Делай **приватный** — в репозитории лежит логика канала, а бесплатных минут Actions на приватном
хватает с запасом (2000 в месяц; один прогон ≈ 2-3 минуты, семь роликов в день ≈ 600 минут).

```bash
cd speakloud
git init
git add .
git commit -m "SpeakLoud: конвейер роликов для практики английского"
git branch -M main
git remote add origin https://github.com/<твой-логин>/speakloud.git
git push -u origin main
```

`.gitignore` уже закрывает `.env`, `client_secret.json`, токены и папку `out/`. Проверь перед
первым пушем: `git status` не должен показывать ни один из этих файлов.

---

## Шаг 2. Доступ к YouTube API

1. [console.cloud.google.com](https://console.cloud.google.com) → **New Project** → назови `speakloud`.
2. **APIs & Services → Library** → найди **YouTube Data API v3** → **Enable**.
3. **APIs & Services → OAuth consent screen**:
   - User type: **External**
   - Заполни название приложения, свою почту
   - Scopes: добавь `https://www.googleapis.com/auth/youtube.upload`
   - **Нажми «Publish app»** (перевод в Production).

   > Это принципиальный момент. Пока приложение в режиме **Testing**, refresh-токен
   > протухает через **7 дней**, и конвейер молча встанет. В Production токен живёт
   > бессрочно. Проверку Google проходить не обязательно — у неверифицированного
   > приложения будет предупреждение при входе и лимит в 100 пользователей, для своего
   > канала этого достаточно.

4. **Credentials → Create credentials → OAuth client ID → Desktop app** → скачай JSON,
   положи в корень проекта как `client_secret.json`.

## Шаг 3. Refresh-токен (один раз, локально)

```bash
pip install -r requirements.txt
python3 tools/get_youtube_refresh_token.py
```

Откроется браузер — войди **в тот аккаунт, где создан канал**. Скрипт напечатает три значения.
Предупреждение «Google hasn't verified this app» — это ожидаемо, жми Advanced → Go to…

---

## Шаг 4. Секреты репозитория

GitHub → **Settings → Secrets and variables → Actions → New repository secret**:

| Имя | Откуда |
|---|---|
| `ANTHROPIC_API_KEY` | console.anthropic.com → API Keys |
| `YT_CLIENT_ID` | вывод скрипта из шага 3 |
| `YT_CLIENT_SECRET` | вывод скрипта из шага 3 |
| `YT_REFRESH_TOKEN` | вывод скрипта из шага 3 |

Затем **Settings → Actions → General → Workflow permissions** → **Read and write permissions**.
Без этого воркфлоу не сможет коммитить `state.json` с очередью тем, и темы начнут повторяться.

---

## Шаг 5. Первый запуск руками

Actions → **publish** → **Run workflow**:

- первый прогон: `upload = false` — соберётся ролик, скачай его из **Artifacts** и посмотри
- в `config.json` поставь `publish.youtube.privacy: "unlisted"` на первые несколько дней,
  чтобы посмотреть на результат в интерфейсе YouTube, не показывая его подписчикам
- когда доволен — `"public"`, и дальше по расписанию

Расписание уже стоит на 09:00 и 19:00 МСК. GitHub может задержать запуск на 5-30 минут
в часы пик — на канале это никак не сказывается.

## Шаг 6. Рост до 6-7 роликов в день

Три места, которые нужно поправить синхронно:

**1. `config.json` → `publish.slots`** — добавь слоты:

```json
{"name": "noon", "cron": "0 9 * * *", "local": "12:00 МСК", "pool": "morning", "level": "A2-B1"}
```

**2. `.github/workflows/publish.yml`** — та же строка cron в `on.schedule` и запись в `SLOT_MAP`:

```yaml
    - cron: "0 11 * * *"
...
            {..., "0 11 * * *": "midday"}
```

Время выхода не строгое: шаг «Случайная задержка» сдвигает публикацию на 0..`jitter_minutes`
минут после cron (по умолчанию 20). Настраивается в `config.json` → `publish.jitter_minutes`.
Учти: задержка тратит минуты GitHub Actions. На **приватном** репозитории держи её ≤20;
на **публичном** минуты бесплатны и без лимита — там можно ставить сколько угодно.

**3. `topics.json`** — если завёл новый пул тем, добавь его разделом. На 7 роликов в день
одного пула из 20 тем мало: темы начнут повторяться через три дня. Держи в каждом пуле
60-100 тем — тогда цикл больше двух недель.

### Жёсткий потолок: квота YouTube API

Дневная квота проекта — **10 000 единиц**. Одна загрузка `videos.insert` стоит **1600**,
установка обложки — **50**. Считаем:

| Роликов в день | Расход | Влезает? |
|---|---|---|
| 2 | 3 300 | да, с запасом |
| 4 | 6 600 | да |
| 6 | 9 900 | впритык, любой перезапуск упадёт |
| 7 | 11 550 | **нет** |

Так что 6 в день — реальный потолок одного проекта, и то без права на ошибку. Варианты для 7+:

- подать заявку на увеличение квоты (YouTube API Services — Audit and Quota Extension Form),
  рассматривают недели и требуют описать сервис;
- завести второй проект Google Cloud со своими ключами и разложить слоты между двумя наборами
  секретов (`YT_CLIENT_ID_2` и т.д.);
- не ставить обложку через API (экономит 50 единиц — погоды не делает, но чуть отодвигает край).

Мой совет: доведи до 4-5 в день и смотри на удержание. Больше роликов ≠ больше просмотров,
а вот качество тем и разнообразие фонов на удержание влияют сильно.

## Что почём

| Статья | Расход |
|---|---|
| GitHub Actions | ~2-3 мин рендер + до `jitter_minutes` ожидания на ролик. 4 в день с jitter 20 ≈ 1500 мин/мес — впритык к 2000 бесплатным на приватном. Хочешь чаще и с большим разбросом — сделай репозиторий публичным: там Actions без лимита |
| Claude API | около 1 цента за монолог с метаданными |
| YouTube API | бесплатно в пределах квоты |

## Если что-то сломалось

| Симптом | Причина | Что делать |
|---|---|---|
| `invalid_grant` при загрузке | приложение осталось в Testing, токен протух через 7 дней | Publish app в consent screen, перевыпустить токен шагом 3 |
| `quotaExceeded` | упёрлись в 10 000 единиц | подождать сброса (полночь по тихоокеанскому времени) или сократить слоты |
| Темы повторяются | `state.json` не коммитится | включить Read and write permissions (шаг 4) |
| Воркфлоу не запускается по расписанию | в репозитории 60 дней не было активности — GitHub отключает cron | зайти в Actions и нажать Enable workflow, либо коммитить хоть что-то раз в месяц |
| Ролик собрался, но текст не тот | нет `ANTHROPIC_API_KEY` — взялась заготовка | проверить секрет |
| `Failed to push state.json` | параллельные прогоны | `concurrency` в воркфлоу это уже предотвращает; если всё же — перезапустить job |
